\section{How to read this document}

Every API feature in the AgriScan monorepo (\code{apps/api} --- Django~5 +
DRF + SimpleJWT), with its endpoints, request/response contracts, business
rules and current implementation status.

\subsection*{Status legend}
\begin{itemize}
  \item \done\ --- endpoint exists, is wired to the frontend, and works
        end-to-end in the current build.
  \item \partialstatus\ --- code exists but has a known gap (no live
        credentials, duplicate logic, unvalidated, or dead route).
  \item \planned\ --- described in the roadmap/docs, not built.
  \item \legacy\ --- old server-rendered Django view kept for backward
        compatibility; superseded by a JSON endpoint.
\end{itemize}

\subsection*{Base URLs}
\begin{itemize}
  \item API base (JSON): \code{http://localhost:8000/api/v1/} in dev,
        \code{https://api.agriscan.co.ke/api/v1/} in production (behind nginx).
  \item Web app: \code{http://localhost:3000} (Next.js), reads the base from
        \code{NEXT\_PUBLIC\_API\_URL}.
  \item A few non-prefixed routes live at the site root (M-Pesa callback,
        legacy HTML views, allauth) --- flagged inline below.
\end{itemize}

\end{tabularx}

\subsection*{Authentication model}
\begin{itemize}
  \item \textbf{SPA (browser/app):} Bearer JWT. Access token
        \code{agriscan\_access} + refresh \code{agriscan\_refresh} in
        \code{localStorage}; 30-minute idle timeout enforced both client
        and server (\code{IdleTimeoutJWTAuthentication}).
  \item \textbf{Machine-to-machine (lenders):} \code{Authorization: Bearer
        <LendingAPIKey raw secret>}, hashed at rest; a legacy plaintext
        \code{PartnerAPIKey} is still accepted while
        \code{ALLOW\_LEGACY\_PARTNER\_KEYS} or \code{DEV\_ENV} is on.
  \item \textbf{Role resolution} is implicit: the profile relation a user
        owns (\code{farmer\_profile}, \code{buyer\_profile},
        \code{agency\_profile}, \code{lending\_partner\_profile}) decides the
        role; \code{is\_staff} maps to admin. Custom permissions:
        \code{IsFarmer}, \code{IsBuyer}, \code{IsAgency},
        \code{IsLendingPartner}, \code{IsApprovedLendingPartner},
        \code{IsStaffUser} --- all in \code{accounts/permissions.py}.
\end{itemize}

\subsection{F2 --- Registration \& session (auth)}
\begin{center}
\small
\begin{tabularx}{\textwidth}{@{} l X l @{}}
\toprule
\textbf{Method \& path} & \textbf{Purpose} & \textbf{Access} \\
\midrule
\code{POST /auth/register/farmer/}    & farmer signup  & anon, \code{auth} throttle \\
\code{POST /auth/register/buyer/}     & buyer signup (multipart: photo) & anon \\
\code{POST /auth/register/agency/}    & input-agency signup & anon \\
\code{POST /auth/register/lender/}    & lender signup  & anon \\
\code{POST /auth/login/}              & JWT pair; email \emph{or} username & anon \\
\code{POST /auth/refresh/}            & rotate access token (idle-aware) & anon \\
\code{POST /auth/logout/}             & blacklist refresh token & authed \\
\code{GET  /me/}                      & current user + role + profile + wallet & authed \\
\code{PATCH /me/}                     & update profile fields & authed \\
\code{GET  /weather/}                 & OpenWeather for farmer/buyer location & farmer/buyer \\
\bottomrule
\end{tabularx}
\end{center}

\textbf{Status:} \done\ (Google OAuth also available via django-allauth at
root \code{/accounts/}).

Registration contract: common fields \code{email} (required),
\code{password} (min 8), optional \code{username}/\code{first\_name}/\code{last\_name};
role extras --- farmer: \code{phone\_number}, \code{county};
buyer: \code{phone\_number}, \code{county}, \code{photo} (image, required);
agency: \code{agency\_name}, \code{agency\_type}, \code{phone}, \code{county};
lender: \code{organization\_name}, \code{organization\_type},
\code{registration\_number}, \code{contact\_phone}, \code{county}.

Returns \code{201} with \code{\{access, refresh, role, user\}}; the client
then calls \code{GET /me/} for the full profile.

\code{GET /me/} payload shape:
\begin{verbatim}
{"user":  {...}, "role": "farmer",
 "profile": {..., "health_score", "risk_tier",
             "opt_in_for_lending"},
 "wallet": {"balance": "0.00",
            "scan_count": 0, "chat_count": 0}}
\end{verbatim}
(\code{wallet} only present for farmers; \code{null} otherwise.)

Profile updates via \code{PATCH /me/}: names, email, phone, county,
country, products, farm fields, profile photo (or
\code{clear\_profile\_photo}), agency/lender organisation fields, and the
\code{opt\_in\_for\_lending} consent flag.

\subsection{F3 --- Crop scan pipeline (core product)}
\begin{center}
\small
\begin{tabularx}{\textwidth}{@{} l X l @{}}
\toprule
\textbf{Method \& path} & \textbf{Purpose} & \textbf{Access} \\
\midrule
\code{GET  /crops/}        & crop catalogue + disease classes & farmer \\
\code{POST /scans/}        & upload image, enqueue Celery job & farmer, \code{scans} throttle \\
\code{GET  /scans/}        & last 50 jobs for the user & farmer \\
\code{GET  /scans/<job\_id>/} & poll job status/result + wallet balance & farmer \\
\bottomrule
\end{tabularx}
\end{center}

\textbf{Status:} \done\ (async, queue-guarded).

\textbf{Business rules:}
\begin{itemize}
  \item Image must be an image, $\leq$\,5\,MB.
  \item \textbf{2 free scans} (\code{wallet.scan\_count < 2}); after that each
        scan costs \textbf{KSh 20} --- \code{402 Payment Required} with
        \code{\{required, balance\}} when the wallet is short.
  \item Global queue cap \code{MAX\_QUEUED\_SCAN\_JOBS=20} $\rightarrow$
        \code{503} + \code{Retry-After: 30}.
  \item Per-user cap \code{MAX\_QUEUED\_SCANS\_PER\_USER=3} $\rightarrow$
        \code{429} + \code{Retry-After}.
  \item Enqueue failure $\rightarrow$ job marked \code{failed}, image cleaned
        up, \code{503} returned.
  \item Job statuses: \code{queued $\rightarrow$ processing $\rightarrow$
        completed | rejected | failed}.
\end{itemize}

Result payload (on \code{GET /scans/<id>/}): \code{result\_label},
\code{confidence}, \code{report} (JSON: overview, recommendations,
prevention, severity, etc.), \code{gatekeeper\_passed},
\code{error\_message}, timestamps, plus live \code{wallet\_balance}.

\code{GET /crops/} returns every known crop with its disease class list and
a \code{supported} flag (membership in \code{SUPPORTED\_SCAN\_CROPS} --- 18
crops listed; only 11 \code{.h5} weights are committed, the rest require
\code{manage.py sync\_models}).

\subsection{F4 --- AgriBot chat (RAG + LLM)}
\begin{center}
\small
\begin{tabularx}{\textwidth}{@{} l X l @{}}
\toprule
\textbf{Method \& path} & \textbf{Purpose} & \textbf{Access} \\
\midrule
\code{POST /chat/messages/} & ask AgriBot, get structured advice & farmer, \code{chat} throttle \\
\bottomrule
\end{tabularx}
\end{center}

\textbf{Status:} \done\ (English + Kiswahili). RAG, weather and LLM calls
all run \emph{inside} the request (no Celery), so latency and failures are
user-visible.

Flow: strip HTML from \code{message} $\rightarrow$ check wallet
(\textbf{5 free chats}, then \textbf{KSh 10} each; \code{402} with
\code{needs\_topup:true} if short) $\rightarrow$ build context (farmer name,
county, live weather, RAG snippets capped at 4500 chars) $\rightarrow$
\code{ChatGroq} at temperature 0.3 $\rightarrow$ parse JSON.

Response shape:
\begin{verbatim}
{"response": {"overview", "diagnosis",
              "recommendations": [...],
              "prevention", "weather_note", "local_tip"},
 "wallet_balance": "90.00", "chat_count": 6,
 "farmer": {"name": "...", "location": "Nakuru, Kenya"}}
\end{verbatim}
On LLM/JSON-parse failure the API still returns \code{200} with a degraded
\code{response} object (empty \code{diagnosis}, error text folded into
\code{local\_tip}).

\subsection{F7 --- Wallet \& M-Pesa top-up}
\begin{center}
\small
\begin{tabularx}{\textwidth}{@{} l X l @{}}
\toprule
\textbf{Method \& path} & \textbf{Purpose} & \textbf{Access} \\
\midrule
\code{GET /wallet/}                 & balance, \code{scan\_count}, \code{chat\_count} & farmer \\
\code{POST /mpesa/topup/}           & initiate Daraja STK push & farmer, \code{payments} throttle \\
\code{POST /mpesa/callback/} \textit{(root)} & Safaricom result callback & IP allowlist \\
\bottomrule
\end{tabularx}
\end{center}

\textbf{Status:} \partialstatus\ --- sandbox credentials work; production
cutover is an open roadmap item.

Top-up request: \code{\{amount, phone\_number\}} (decimal, serializer-bounded).
Response: \code{200} with
\code{\{status:"Success", message, checkout\_request\_id\}} or \code{502}
when Daraja rejects the push.

Callback semantics: look up \code{MpesaTransaction} by
\code{CheckoutRequestID}; \code{ResultCode == 0} $\rightarrow$
\code{status='Success'} and \code{wallet.balance += amount}; otherwise
\code{status='Failed'}. Always answers \code{200 \{ResultCode: 0\}}.

\textbf{Known gaps:}
\begin{itemize}
  \item The callback credits \code{mpesa\_txn.amount} (the value set at
        initiation) without confirming against Safaricom, and the IP
        allowlist is inert when \code{MPESA\_CALLBACK\_ALLOWLIST} is empty
        (default) or \code{DEV\_ENV=True} --- a forged callback can credit
        the wallet.
  \item Code reads \code{CONSUMER\_KEY}/\code{CONSUMER\_SECRET} while
        \code{infra/.env.example} ships \code{MPESA\_CONSUMER\_*}; sandbox
        shortcode/passkey are hardcoded as fallbacks
        (\code{mpesa\_utils.py:13-17}).
\end{itemize}

        creation/reads do not.
\end{itemize}

\subsection*{Environment matrix}
\begin{enumerate}
  \item \textbf{Laptop dev:} \code{DEV\_ENV=True} (throttles off, CORS open,
        LocMem cache) --- the README quick path.
  \item \textbf{Production-like:} \code{DEV\_ENV=False} behind
        \code{docker compose -f docker-compose.yml} + nginx (Redis cache,
        throttles on, HTTPS). The README's plain \code{docker compose up}
        also loads \code{docker-compose.override.yml}, which re-exposes
        5432/6379/8000 and forces \code{DEBUG=True} --- not a production run.
\end{enumerate}

\subsection*{Error-contract conventions}
\begin{itemize}
  \item DRF field errors $\rightarrow$ \code{400} with field-keyed dict.
  \item Domain errors $\rightarrow$ \code{400/401/403/404} with
        \code{\{"detail": "...\}} or \code{\{"error": "...\}} --- two
        different keys are in use.
  \item Payment required $\rightarrow$ \code{402}.
  \item Backpressure $\rightarrow$ \code{429}/\code{503} with \code{Retry-After}.
\end{itemize}
